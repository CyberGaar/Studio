## Security design

- pnpm is integrity-pinned to version `11.20.0`, published on 2026-08-03 and older than the required seven-day quarantine at task creation.
- A single workspace lockfile covers the root, database schema, and data-contract packages.
- `minimumReleaseAge: 10080` and `minimumReleaseAgeStrict: true` reject dependency releases younger than seven days, including transitive dependencies.
- Exact direct dependency versions, strict engines, frozen installs, registry TLS, lockfile integrity, dependency review, OSV-Scanner, and `pnpm audit` remain independent gates.
- Dependency lifecycle scripts fail closed; only the reviewed `prisma` and `@prisma/engines` packages may run required build scripts.
- Age is a quarantine control, not proof of safety. Critical and High findings still block merge regardless of package age.
- Emergency security releases younger than seven days require a separate reviewed security task; this policy contains no automatic bypass.

## Acceptance criteria

- No npm lockfile remains and exactly one `pnpm-lock.yaml` is tracked.
- Operational scripts, validators, and current documentation use pnpm.
- The pinned pnpm version and integrity are declared in the root manifest.
- `pnpm install --frozen-lockfile` succeeds without changing the lockfile.
- Database schema and contract validation pass under pnpm.
- Dependency, secret, disclosure, SPDX, allowlist, and clean-room gates pass.
