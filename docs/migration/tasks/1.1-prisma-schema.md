## Security decisions

- Prisma tooling is exact-pinned and upgraded from the snapshot's Prisma 5.22.0 to Prisma 7.9.1.
- Dynamic rehearsals use `pgvector/pgvector@sha256:691673308c99d2161ba298736f3147f1f22d79de2fb7ec93ae9b4afcab870b62`; the baseline explicitly creates the required `vector` extension.
- Raw passwords are prohibited. The legacy database password column is exposed only as nullable `passwordHash`; identity authentication will be owned by Kratos.
- CASB and user-integration secret material is stored only as envelope-encrypted ciphertext plus key identifier and version. JSON configuration fields are explicitly non-secret.
- Synthetic fixture passwords are generated per run, never logged, and written only to a Git-ignored restricted file. Usernames and roles may be logged for operator usability.
- Projects require a customer owner. Project-to-evidence links carry that customer identifier and use composite foreign keys to both records, so PostgreSQL rejects cross-tenant links independently of application code.
- No real seed data, database dump, runtime database, or generated client is committed.

## Verification plan

1. `npm ci --ignore-scripts` in `database/schema`.
2. `npm run validate` and `npm run generate:check`.
3. Recreate the baseline with `prisma migrate diff --from-empty` and prove byte-for-byte equality.
4. Start isolated PostgreSQL and run `prisma migrate deploy` against an empty database.
5. Apply synthetic fixtures and verify tenant separation, hashes, uniqueness, foreign keys, and credential-file permissions.
6. Rehearse populated edge cases in isolated copies before staging approval.

## Local dynamic rehearsal evidence

The pinned pgvector image was started with disposable storage. The canonical baseline deployed to an empty database, the fixtures ran twice, and a second migration deployment reported no pending migrations. Assertions passed for six users, two tenant projects, two same-named tenant-scoped evidence records, two valid links, zero cross-tenant links, bcrypt-formatted hashes, no plaintext credential columns, and the vector extension. A deliberate cross-tenant insert was rejected with SQLSTATE `23503`.

The credential handoff file and container were destroyed after the rehearsal. This local result makes the task ready for repository review; it does not replace the required feature-branch staging test or its PR evidence.
